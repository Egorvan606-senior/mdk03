# Сценарий внедрения клиентского модуля ИС «Умный кампус» на АРМ оператора проходной

Версия клиента: Campus Operator 2.4.0 · утилита выгрузки ведомостей campus-meal-statement 1.0

## 1. Требования к операционной среде

| Параметр | Требование | Как проверить |
|---|---|---|
| ОС | Windows 10 22H2 / Windows 11 x64, последние обновления безопасности | `winver` |
| Платформа | .NET 8 Desktop Runtime 8.0.x (x64) | `dotnet --list-runtimes` → `Microsoft.WindowsDesktop.App 8.0.*` |
| Процессор / ОЗУ | 2 ядра, 4 ГБ ОЗУ (рекомендуется 8 ГБ) | Диспетчер задач |
| Диск | 2 ГБ свободно на `C:` (программа, кэш фото, журналы, 3 резервные копии) | `Get-PSDrive C` |
| Дисплей | 1920×1080, масштаб 100–125 % | Параметры экрана |
| Сеть: HTTPS | исходящий **TCP 443** к API кампуса `campus-api.spbiem.local` | `Test-NetConnection campus-api.spbiem.local -Port 443` |
| Сеть: телеметрия | исходящий **TCP 4317** (OTLP gRPC) к коллектору `otel.spbiem.local` | `Test-NetConnection otel.spbiem.local -Port 4317` |
| Считыватель | контроллер в той же VLAN, TCP 4001 | `Test-NetConnection <IP контроллера> -Port 4001` |
| Время | синхронизация с доменным NTP (расхождение < 1 с — важно для журналов и трассировки) | `w32tm /query /status` |
| Учётные записи | доменная УЗ оператора (роль «Оператор поста»), служебная `svc-campus-update` для обновлений | ADUC |

## 3. Технический сценарий развертывания

| Шаг | Действие | Результат |
|---|---|---|
| 0 | Пройти чек-лист раздела 2, приложить его к заявке на внедрение | чек-лист без критичных «Нет» |
| 1 | Установить .NET 8 Desktop Runtime (`windowsdesktop-runtime-8.0.x-win-x64.exe /quiet /norestart`) | runtime в списке `dotnet --list-runtimes` |
| 2 | Задать секрет: `setx CAMPUS_API_KEY "<ключ из хранилища секретов>" /M` (выполняет администратор) | переменная на уровне системы |
| 3 | Скопировать дистрибутив в `C:\Program Files\SmartCampus\Operator`, проверить SHA-256 по `manifest.json` | файлы на месте, суммы совпадают |
| 4 | Создать `appsettings.json` из шаблона: адреса API, номер АРМ, IP считывателя (без секретов) | конфигурация АРМ |
| 5 | Создать папки `C:\ProgramData\Campus\{logs,backups,cache}` и выдать группе `Campus-Operators` права «Изменение» только на них | разграничение прав |
| 6 | Первый запуск под оператором, вход, выбор роли и поста | все индикаторы зелёные |
| 7 | Тестовый проход служебной картой, проверка записи в журнале и на сервере | запись видна в обоих журналах |
| 8 | Для АРМ столовой: пробная выгрузка ведомости `campus-meal-statement --month <тек. месяц>` | 3 CSV + файл SHA-256 |
| 9 | Оформить акт ввода в эксплуатацию, внести АРМ в CMDB | АРМ в учёте |

Откат внедрения: удалить каталог программы и переменную `CAMPUS_API_KEY` (`REG delete "HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment" /v CAMPUS_API_KEY /f`), вернуть прежний порядок работы поста.

## 4. Правила безопасной передачи ключей доступа

1. **Секреты не хранятся в `appsettings.json` и в репозитории.** В конфигурации указывается
   только *имя* переменной окружения:

   ```json
   "Secrets": { "ApiKeyEnvVariable": "CAMPUS_API_KEY" }
   ```

   Программа читает значение при запуске: `Environment.GetEnvironmentVariable("CAMPUS_API_KEY")`.
2. Переменная создаётся администратором на уровне **системы** (`setx … /M`), значение
   берётся из корпоративного хранилища секретов и передаётся только по защищённому каналу
   (не по почте и не в мессенджере).
3. Иерархия источников конфигурации .NET (`appsettings.json` → `appsettings.{Environment}.json`
   → переменные окружения) позволяет переопределить любой параметр без правки файлов:
   например, `CampusApi__BaseUrl` перекрывает ключ `CampusApi:BaseUrl`.
4. Права на файл `appsettings.json`: чтение для `Campus-Operators`, изменение — только администраторам.
5. Ключ не выводится в журналы и в окна программы; в трассировке OpenTelemetry не передаются
   заголовки `Authorization`.
6. Ротация ключа — раз в 90 дней и немедленно при увольнении администратора или подозрении на
   компрометацию; после смены — перезапуск клиента.
7. Для разработки на ПК программиста — `dotnet user-secrets`, а не файлы в репозитории.
