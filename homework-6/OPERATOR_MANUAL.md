# Руководство оператора

**ИС «Умный кампус». АРМ оператора поста охраны (клиент Campus Operator 2.4.0)**

Документ составлен по структуре ГОСТ 19.505-79 «ЕСПД. Руководство оператора».

## 1. Назначение программы

Программа Campus Operator предназначена для контроля прохода студентов и сотрудников
в здания кампуса и спорткомплекс:

* отображение сведений о владельце пропуска при поднесении карты к считывателю;
* разрешение или запрет прохода, ручной пропуск по решению оператора;
* ведение журнала проходов и его синхронизация с центральной БД;
* работа в автономном режиме по локальному кэшу пропусков при потере связи с сервером.

## 2. Условия выполнения программы

* ОС Windows 10/11 (x64), .NET 8 Desktop Runtime;
* подключённый контроллер считывателя пропусков (Parsec NR-EH03, сеть, порт 4001);
* доступ к сети кампуса (API — порт 443, центральная БД — 5432, телеметрия — 4317);
* учётная запись оператора в домене кампуса с ролью «Оператор поста».

## 3. Выполнение программы

### 3.1. Вход

1. Включите АРМ и войдите в Windows под своей учётной записью.
2. Запустите **Campus Operator** ярлыком на рабочем столе.
3. Проверьте строку состояния внизу окна: все индикаторы должны быть зелёными —
   «Сервер», «БД», «Считыватель». Номер версии отображается справа (2.4.0).
4. Выберите пост («Спорткомплекс, вход № 2») и нажмите **Начать смену**.

### 3.2. Базовые операции

| Операция | Действия оператора |
|---|---|
| Проход по пропуску | владелец подносит карту; на экране — фото, ФИО, статус. Зелёная рамка — проход разрешён автоматически |
| Проход запрещён | красная рамка и причина (пропуск заблокирован / истёк). Сверьте фото, при необходимости вызовите дежурного администратора |
| Ручной проход | кнопка **Ручной проход** → укажите ФИО и причину → **Подтвердить**. Запись попадает в журнал с отметкой оператора |
| Поиск по журналу | вкладка **Журнал** → фильтр по дате, номеру карты или ФИО |
| Завершение смены | **Завершить смену** → дождитесь сообщения «Журнал синхронизирован» → закройте программу |

### 3.3. Проверка после обновления программы

После ночного обновления в начале смены:

1. Убедитесь, что в правом нижнем углу указана версия **2.4.0**.
2. Проверьте индикаторы «Сервер», «БД», «Считыватель».
3. Поднесите служебную тестовую карту — должна появиться запись «Тестовый проход».
4. При любом расхождении — раздел 4.

## 4. Сообщения оператору и действия при сбоях

| Сообщение / признак | Причина | Действия оператора |
|---|---|---|
| Индикатор «Сервер» красный, «Автономный режим» | нет связи с API кампуса | работайте в автономном режиме (проходы сохраняются локально). Сообщите в Service Desk, тел. 1234. После восстановления связи журнал синхронизируется сам |
| «Считыватель не отвечает» | отключён кабель или питание контроллера | проверьте кабель и индикатор питания считывателя; пропускайте по **Ручному проходу**, сообщите в Service Desk |
| «Локальная база повреждена» | сбой диска или аварийное выключение | не перезапускайте АРМ повторно, вызовите администратора: он восстановит базу из резервной копии |
| После обновления версия осталась старой, в журнале — «Обновление отменено» | обновление не прошло проверку и было откатано автоматически | работайте как обычно на предыдущей версии; администратор уже получил инцидент |
| Программа не запускается | повреждение установки | сообщите администратору: ручной откат по UPDATE_GUIDE.md, раздел 5 |

Во всех случаях укажите в обращении номер АРМ (например, **ARM-SPORT-01**), время и текст сообщения.
