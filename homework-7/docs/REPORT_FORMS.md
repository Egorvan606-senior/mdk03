# Отчётные формы и журналы учёта ИС «Умный кампус»

Общие требования ко всем формам:

* **Полнота данных** — в отчёт попадают все записи за период; итоговые строки вычисляются
  программой; число записей и контрольная сумма указываются в подвале отчёта.
* **Защита от изменений** — записи журналов в БД только добавляются (append-only, права
  `INSERT` без `UPDATE/DELETE`); исправление — корректирующей записью со ссылкой на исходную;
  к каждой выгрузке формируется файл SHA-256, PDF подписывается электронной подписью ответственного.
* **Экспорт** — Excel (CSV для Excel с разделителем «;» и UTF-8 BOM, либо XLSX) для анализа и
  PDF/A для архива и печати; имя файла: `<отчёт>_<период>.<расширение>`.
* **Доступ** — по ролям; каждая выгрузка фиксируется в журнале аудита (кто, когда, какой отчёт).

## 1. Журнал регистрации проходов через турникеты

Назначение: учёт входа/выхода по пропускам, расследование инцидентов, табель посещаемости.
Периодичность: оперативно (экран оператора), выгрузка — сутки / месяц.

| № | Поле | Тип | Обяз. | Описание / пример |
|---|---|---|---|---|
| 1 | Номер записи | bigint, автонумерация | да | сквозной номер, без пропусков — контроль полноты |
| 2 | Дата и время прохода | timestamptz | да | `23.10.2026 08:41:15`, время сервера NTP |
| 3 | Корпус / точка прохода | справочник | да | «Спорткомплекс, вход № 2» |
| 4 | Турникет / считыватель | строка | да | `T-SPORT-02` |
| 5 | Направление | перечисление | да | Вход / Выход |
| 6 | Номер карты | строка | да | `C100068` |
| 7 | Владелец пропуска | ФИО + табельный/студ. номер | да | «Иванов Е.М., ST200004» |
| 8 | Категория | перечисление | да | Студент / Сотрудник / Гость |
| 9 | Результат | перечисление | да | Разрешён / Запрещён / Ручной проход |
| 10 | Причина отказа / основание ручного прохода | строка | при отказе/ручном | «Пропуск заблокирован» |
| 11 | Оператор | УЗ домена | при ручном | `spbiem\petrova` |
| 12 | Режим | перечисление | да | Онлайн / Автономный (синхронизировано позже) |
| 13 | TraceId | строка | да | идентификатор трассы для поиска в журналах |

Защита: запись создаётся только программой; удаление запрещено; хранение — 1 год онлайн, 3 года в архиве.
Экспорт: Excel (фильтры по дате, корпусу, владельцу), PDF за сутки для службы безопасности.
Подвал: «Записей: N, ручных проходов: M, отказов: K, SHA-256: …».

## 2. Отчёт по загруженности аудиторий за месяц

Назначение: планирование расписания, выявление недогруженных и перегруженных аудиторий.
Периодичность: ежемесячно до 3-го числа.

| № | Поле | Тип | Обяз. | Описание / пример |
|---|---|---|---|---|
| 1 | Корпус | справочник | да | «Корпус А» |
| 2 | Аудитория | строка | да | «А-305» |
| 3 | Тип | перечисление | да | Лекционная / Компьютерный класс / Спортзал |
| 4 | Вместимость, мест | integer | да | 30 |
| 5 | Доступный фонд, ч | decimal | да | рабочие часы аудитории в месяце (например, 22 дня × 12 ч = 264) |
| 6 | Занято по расписанию, ч | decimal | да | сумма длительностей занятий (из диапазонов времени, см. CAMPUS-110) |
| 7 | Занято по бронированию, ч | decimal | да | внеплановые брони |
| 8 | Загруженность, % | decimal | да | (п.6 + п.7) / п.5 × 100 |
| 9 | Средняя наполняемость, % | decimal | нет | фактически пришедших (по журналу проходов) / вместимость |
| 10 | Пиковый час | время | нет | «10:00–11:30» |
| 11 | Отклонения | строка | нет | «загрузка < 30 %», «пересечение броней» |

Полнота: в отчёт включаются все аудитории из справочника, в том числе с нулевой загрузкой.
Защита: отчёт формируется из неизменяемого снимка расписания на 1-е число; повторная выгрузка
за тот же месяц получает новый номер версии. Экспорт: Excel (с условным форматированием
загрузки), PDF для учебного отдела. Итоги: по корпусу и по кампусу.

## 3. Ведомость учёта питания в столовой

Назначение: финансовый учёт выручки столовой, расчёт дотаций на льготное питание, сверка
с кассой и бухгалтерией. Периодичность: ежемесячно, оперативно — за смену.
Реализована утилитой `campus-meal-statement` (вариант 10) в трёх файлах.

### 3.1. Финансовый лог `meal_transactions_ГГГГ-ММ.csv`

| № | Поле | Тип | Обяз. | Пример |
|---|---|---|---|---|
| 1 | № | integer | да | 1 |
| 2 | ID транзакции | строка, уникальная | да | `TX-202610-00032` |
| 3 | Дата | date | да | 01.10.2026 |
| 4 | Время | time | да | 09:44 |
| 5 | Карта | строка | да | C100068 |
| 6 | Студент | строка | да | ST200004 |
| 7 | Категория | перечисление | да | Завтрак / Обед (комплекс) / Буфет / Ужин |
| 8 | Порций | integer | да | 1 |
| 9 | Цена, руб. | decimal(10,2) | да | 125,00 |
| 10 | Сумма, руб. | decimal(10,2) | да | = цена × порций |
| 11 | Дотация, руб. | decimal(10,2) | да | 50 % стоимости обеда для льготников |
| 12 | К оплате, руб. | decimal(10,2) | да | = сумма − дотация |
| 13 | Способ оплаты | перечисление | да | Карта студента / Карта студента + дотация / Наличные |
| 14 | Касса | справочник | да | Касса 1 (корпус А) |

### 3.2. Ведомость по категориям `meal_statement_ГГГГ-ММ.csv`

Строка-заголовок с периодом, временем формирования и источником данных (или пометкой
«ПО ДАННЫМ КЭША»), затем по каждой категории: транзакций, порций, сумма, дотация, к оплате,
средний чек, доля выручки %, и строка **ИТОГО**.

### 3.3. Сводная по студентам `meal_by_student_ГГГГ-ММ.csv`

Студент, карта, сумма к оплате по каждой категории, дотация, итого; строка ИТОГО —
для передачи в соцотдел (дотации) и бухгалтерию.

**Контроль полноты:** число транзакций и итоговая сумма в трёх файлах совпадают; номера
транзакций уникальны (при дубликате выгрузка прерывается).
**Защита от изменений:** файл `meal_statement_ГГГГ-ММ.sha256` с контрольными суммами
SHA-256 всех трёх CSV; бухгалтерия проверяет его при приёме (`Get-FileHash`).
**Экспорт:** CSV для Excel (UTF-8 BOM, «;», десятичная запятая); PDF-версия ведомости
для подписи заведующим столовой.
