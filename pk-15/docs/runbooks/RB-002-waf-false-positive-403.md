# Runbook RB-002. WAF блокирует легитимные запросы мобильного приложения (403)

**Сервис:** Ingress NGINX + ModSecurity перед OrderService · **Кейс 10 (вариант 10)**
**Алерт:** `WafMobile403Rate` — доля 403 от WAF на трафике `channel=mobile` > 0,5 % за 5 минут

## Шаг 1. Диагностика

Найдите заблокированные запросы и номер сработавшего правила:

```bash
kubectl logs -n ingress-nginx deploy/ingress-nginx-controller --since=10m | grep -i "ModSecurity: Access denied" | tail -20
```

* В строке есть `[id "9421xx"]` / `[id "9411xx"]` и URI `/api/v1/orders` с телом JSON от
  мобильного приложения — это **ложное срабатывание** → **Шаг 2**.
* Запросы с одного IP, перебор параметров, явные `UNION SELECT` — это **атака**, WAF работает верно.
  Ничего не меняйте, сообщите в канал безопасности.

## Шаг 2. Действие

Переведите WAF в режим наблюдения — запросы перестанут блокироваться, но продолжат журналироваться:

```bash
kubectl apply -f deploy/k8s/order-service-ingress-waf-detection.yaml
```

Проверьте: оформление заказа из мобильного приложения проходит, заголовок ответа `X-Waf-Mode: DetectionOnly`.

## Шаг 3. Эскалация

Если **через 2 минуты** доля ошибок не снизилась — свяжитесь с дежурным архитектором в **`#emergency-sre`**,
приложите номер правила (`id`) и TraceId запроса. Исключение для правила добавляется в
`modsecurity-snippet` отдельным изменением (Change Request), после чего режим `On` возвращается.
