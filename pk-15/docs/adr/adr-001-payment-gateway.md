# ADR-001. Подключение нового платёжного шлюза через интерфейс IPaymentService

**Статус:** Утверждено.

**Дата:** 21.10.2026 · **Автор:** Иванов Е.М. · **Связано с:** релиз OrderService 2.0.0, ADR-002

## Контекст

Требуется подключить новый безопасный платёжный шлюз с поддержкой протокола **3D-Secure 2.0**.
Старый шлюз 3-D Secure 2.0 не поддерживает: банки чаще отклоняют такие платежи, а покупатель
не получает frictionless-оплату (без ввода кода) на небольшие суммы. Шлюз поставляется
со своим SDK, формат ответов которого отличается от старого.

## Решение

Интегрируем официальный SDK платёжной системы через абстрактный интерфейс **`IPaymentService`** в C#,
чтобы изолировать бизнес-логику от деталей конкретного вендора.

* `IPaymentService.ChargeAsync(PaymentRequest)` возвращает доменный `PaymentResult`
  (`Approved`, `ChallengeRequired`, `Declined`) — бизнес-логика не видит классов SDK.
* `NewGatewayPaymentService` — адаптер над SDK нового шлюза; `LegacyGatewayPaymentService` — старый шлюз.
* Реализация выбирается в DI по настройке `Payments:Provider`, поэтому платёжную часть можно
  откатить переменной окружения без пересборки.

## Последствия

* **Плюсы:** упрощается написание модульных тестов с использованием **Moq** — шлюз подменяется
  mock-объектом (`tests/OrderService.Tests/RollbackAndPaymentTests.cs`); смена вендора в будущем
  затрагивает только адаптер.
* **Минусы:** требуется **строгая валидация контрактов при изменении версии SDK** — при обновлении
  SDK обязательно прогоняются тесты адаптера и smoke-тест тестовой оплаты, иначе изменение
  формата ответа вендора незаметно сломает оплату.
